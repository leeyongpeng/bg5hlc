## 2. 定位与目标

**一句话**：BG5HLC 的「网络电台室」——别人搜到你的呼号时，能一眼看到你通联过谁、收到了哪些卡片和图像、用什么设备。

**核心诉求**

1. 内容存在 GitHub，有版本历史；
2. 本地写完内容 `push`，网站自动更新，无服务器、无手动上传；
3. 长期零维护、零成本。

**设计原则**

- 内容与外观分离：写内容只碰 `data/`、`content/`，改样式只碰 CSS；
- 无服务器：纯静态，安全、免费、不怕被扫；
- 渐进增强：关掉 JS 也能读到通联卡片和相册，JS 只做筛选、排序、放大；
- **空状态也是设计**：0 条记录时页面不能像坏了，要给「下一步怎么做」的指引。

## 4. 双语与主题（v3 调整）

### 4.1 语言：切换制，不同屏并排

同一时间只显示一种语言，右上角 `EN` / `中文` 切换，构建时生成两套独立页面：

| 地址 | 语言 |
|---|---|
| `/`、`/qso.html`、`/qsl.html` … | 中文（默认） |
| `/en/`、`/en/qso.html` … | English |

- 切换按钮自动指向「当前页面的另一种语言版本」，不需要手写链接；
- 内容用 `.en.md` 后缀提供英文版本，缺字段自动回退中文；
- 界面文案集中在 `sitegen/strings.py`，每条是 `(中文, 英文)`；
- 两套页面都带 `hreflang` 备用链接，便于搜索引擎区分。

### 4.2 主题：浅色 / 深色

右上角是太阳 / 月亮图标按钮，两态切换，选择后记住；没有手动选择时默认浅色。按钮不显示文字。

配色变量在 `assets/css/site-v2.css` 顶部，两套主题各一组，改一个变量即可整体换色。

参考文献给出的配色：纸张米色 `#F6ECD9`、墨绿 `#16241C`、森林绿 `#2F5D3A`、焦橙 `#E8751A`、砖红 `#C1362B`；暗色底 `#0F1A14`。

> 当前实现已全站切换到新版清爽皮肤（`assets/css/site-v2.css`，浅/深两态）。本节描述的复古印刷皮肤保留在 `assets/css/style.css` 里作历史参考，页面已不再加载。

### 4.3 从参考稿吸收的元素

## 5. 页面功能详述

### 5.1 首页

首页使用新版清爽皮肤（`site-v2.css`），放个人信息、电台室设备/天线和 QSL 展示；通联 / SSTV 保持独立页面。

| 区块 | 内容 |
|---|---|
| 顶部 | 呼号、导航 tab（首页 / 通联 / QSL / SSTV / 随笔）、`EN`、日夜图标切换 |
| Hero | 大号呼号、中英简介、网格/分区、主力设备、主力天线、QSL 政策、右侧固定 9 行 ASCII 通联动画（可暂停/单步） |
| 信息条 | 台站信息（国家 / QTH / 网格 / 执照）、日志概况（QSO / DXCC / QSL / SSTV 大数字块）、QSL 政策与联系方式 |
| 电台室 | 设备和天线表直接放在首页；导航里的「电台室」tab 已移除 |
| QSL 展示 | 最近 6 张 QSL 卡片，按时间倒序；有图显示大图，无图用 CSS 卡面；0 张时显示添加指引 |
| 页脚 | 呼号、QTH、构建时间、GitHub |

### 5.2 通联记录 `/qso`

**卡片内容**：日期 / 时间(UTC) · 呼号 · 波段/模式/网格 · 频率/收发 RST；中继 QSO 另有 `REPEATER` 一块（上行 / 下行 / 频差 / 亚音）；本台与对方的 QTH / 设备 / 功率 / 天线 / 架设高度分两栏，本台功率在 `MY STATION` 里。`notes` 只放要做的事，例如交换 QSL 卡片，不放大段技术参数。

**功能**

- 搜索（呼号 / QTH / 设备 / 备注）、波段下拉、模式下拉、排序（最新 / 最早 / 呼号）、显示计数、重置；
- 波段与模式彩色标签（全局统一色标）；
- 宽屏一行两张、窄屏单列；备注完整显示，不截断。

**统计条**：顶部一行显示通联数、DXCC 数、首次/最近通联日期。

**空状态**：一张卡片，列三种录入方式

1. 用 Excel 打开 `data/qso.csv` 直接加行（最直观）；
2. 命令行 `python tools/add_qso.py --call JA1KWF --band 20m --mode SSB --date 2026-03-14`；
3. 有日志软件后，导出 ADIF，用导入脚本一次性灌入。

### 5.3 QSL 卡片 `/qsl` · SSTV `/sstv`

- QSL 页使用新版清爽皮肤：按年份分组的卡片墙、年份筛选、点击放大（lightbox）；
- QSL 卡：对方呼号、日期、波段、模式、收卡方式（卡片局/直寄/eQSL/LoTW）、背面故事；
- SSTV 页使用新版清爽皮肤：4:3 图像卡 + 扫描线叠加、模式标签、年份筛选、点击放大（lightbox）；频率、模式（Scottie 1 / Martin 1 / Robot 36）、接收日期、来源台，保留原始噪点不做美化；
- 空状态：三步添加指引（拍照 → 压缩 → 新建 .md）。

### 5.4 随笔 `/notes`

- Markdown 长文：POTA/SOTA、野外架台、设备评测、天线 DIY；
- 列表页：日期 + 标题 + 摘要；详情页独立 URL；
- RSS `feed.xml`；
- 可选英文摘要 `summary_en`。

### 5.5 电台室（内容合并到首页）

导航里的「电台室」tab 已移除。设备和天线表直接放在首页的「电台室 / STATION」区块；QTH、执照、QSL 政策和联系方式在首页 Hero / 信息条里。

| 区块 | 内容 |
|---|---|
| 设备表 | 型号 / 类别 / 备注（手台、HF 电台、QRP 等） |
| 天线表 | 型号 / 类别 / 架设方式 |
| QTH / 执照 / QSL / 联系 | 首页 Hero 与信息条 |

全部由 `site.config.json` 驱动，加设备只需改配置。旧的 `/station.html` 保留为直接访问地址，但不再出现在导航中。

### 5.6 DXCC 世界地图（新）

- 位置：通联记录页顶部统计条，或独立区块；
- 形式：简化世界轮廓（等距圆柱投影）+ 按 DXCC 实体经纬度打点，点大小/颜色表示通联数，悬停显示「日本 · 12 次」；
- 数据：`data/dxcc.json`（实体名 → 大洲 + 经纬度，约 340 条，一次性准备）；
- 匹配：`data/qso.csv` 的 `dxcc` 字段填标准名称（Japan / Germany / Asiatic Russia…），匹配不上就归入「未归类」并提示；
- 体积目标：SVG < 200KB、gzip 后 < 60KB；
- 兜底方案：若地图体积或精度不理想，退回「按大洲分组的条形图 + 国家标签云」，视觉同样成立。

### 5.7 全局

- 响应式（手机/平板/桌面）；
- 深色主题，呼号用等宽字体；
- SEO：每页独立 `title`/`description`（中英）、Open Graph、`sitemap.xml`；
- `404.html`；
- 页脚显示最近构建时间——一眼确认 push 是否生效。

## 7. 技术方案

### 7.1 选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯 HTML + JS 读 JSON | 零构建 | 首屏闪、SEO 差、索引手写 | 备选 |
| **Python 生成器（自写，零依赖）** | 不装东西、输出纯 HTML、逻辑透明 | 改模板需懂一点 Python | **推荐** |
| Astro | 生态成熟、图片优化 | 需 Node + 一堆依赖 | 备选 |
| Hugo | 快 | 模板门槛高 | 备选 |
| 动态站点 | 能评论、后台 | 要服务器、要钱、有被打风险 | 不采用 |

> 你本机已有 Python 3.15，本地 `python build.py --serve` 就能预览；GitHub Actions 里同样跑这一条命令。

### 7.2 发布链路

```
本地改内容 → git commit → git push
     ↓
GitHub Actions：python build.py（约 20 秒）
     ↓
GitHub Pages：发布到 https://<用户名>.github.io
     ↓
浏览器刷新即可见（CDN 缓存通常 1 分钟内）
```

- 免费账号 Pages 需**公开仓库**（呼号、网格本就是公开信息）；
- 图片建议压缩到单张 300KB 以内；构建时自动生成 900px 缩略图（装了 Pillow 时）；
- 备选：国内访问不稳可迁 Cloudflare Pages，流程同样是 push 即部署。

### 7.3 目录结构

```
BG5HLC/
├── site.config.json      # 呼号、简介、设备、天线、联系方式
├── data/
│   ├── qso.csv           # 通联记录（可先留空）
│   └── dxcc.json         # DXCC 实体经纬度表
├── content/
│   ├── qsl/              # 卡片：1 个 .md + 1 张图
│   ├── sstv/             # 图像：1 个 .md + 1 张图
│   └── notes/            # 随笔
├── assets/               # CSS / JS / favicon / 世界轮廓
├── tools/                # 手动录入、ADIF 导入、图片压缩
├── .github/workflows/    # 自动构建发布
├── build.py              # 生成器入口
└── dist/                 # 构建产物（不入库）
```

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 国内访问 github.io 不稳定 | 迁 Cloudflare Pages（同样免费、push 即部署） |
| 图片太大拖慢加载 | 构建自动缩略图 + 批量压缩脚本 |
| 手写 frontmatter 出错 | 构建报错指明文件与字段；提供骨架生成脚本 |
| 内容泄露隐私 | 只公开呼号与网格，不写详细住址；建议剥离照片 GPS |
| 忘记 push 导致没更新 | 页脚显示最近构建时间，一眼可对 |
| 没有日志导致页面空荡 | 空状态给录入指引；先用示例数据预览效果 |
